## 1. The headline: the conservation invariant earned its keep twice

It was designed to catch the class of bug that produced `Final Total USD: 1` in
the original artifact. It caught two real defects that no test would have found,
and both returned plausible-looking numbers.

### Defect A — the warm-up broke the baseline

Warm-up swaps execute but are not logged, so their flow was missing from the sum
while the pool state already reflected them. The baseline (`initialToken0/1`,
initial price, fee growth) was taken at candle 0 rather than at the end of
warm-up.

Symptom: conservation off by **3.9%**. Fix: `_captureBaseline()` now runs at the
warm-up boundary and records fee growth too, so fees are measured as growth
since the baseline rather than since pool creation.

### Defect B — pandas silently overflowed int64

On a 20M pool the per-swap deltas reach 5.8e18 and the int64 ceiling is 9.2e18.
`Series.sum()` accumulates in int64 and **wraps without raising**:

```
true  flow0 = -10 302 083 318 586 195 069
pandas      =  +8 144 660 755 123 356 547     ← wrong magnitude AND wrong sign
```

Every metric downstream would have been wrong with nothing failing anywhere.
Fix: wei-scale columns are held as object dtype and summed as Python integers
(`exact_sum`). A regression test pins it.

**Worth your attention:** this bug would have silently corrupted the entire
4752-run matrix. It is the single strongest argument for keeping the invariant
in the pipeline rather than treating it as a development aid.

After both fixes, conservation closes at **1.8e-16 across all 12 sweep
configurations** — machine precision.

## 3. Decisions — two resolved, one open

### 3.1 RESOLVED — basket raised to 20,000,000 USDT

A shallow pool needs a large price deviation before a trade clears its gas cost,
because arbitrage profit scales as `V·ε²/4`. One day of ETH/SHIB at 30 bps:

| Basket | 5 gwei | 20 gwei | 80 gwei |
| ------ | ------ | ------- | ------- |
| 1M     | 5      | 1       | 0       |
| 20M    | 25     | 11      | 7       |

**Correction to the first version of this note:** it claimed the 1M pool sees
_zero_ trades at 20 gwei. That figure came from an inflated gas estimate (see
3.2); the correct number is 1. The conclusion is unchanged — a handful of trades
per window is as uninformative as none — but the evidence was overstated.

### 3.2 RESOLVED — gas estimate corrected

`GAS_ESTIMATE` is the cost the arbitrageur assumes when deciding whether a trade
clears its gas, evaluated _before_ the swap because that is the only information
a real arbitrageur has. The realised gas is recorded separately per swap.

The default was **180,000**, a placeholder written into the plan with nothing
behind it. Measured median for `MyHook` is **55,578** of execution gas; adding
the 21,000 intrinsic transaction cost gives **76,578**, now the default. The old
value suppressed roughly twice as many trades as reality.

Plan 2 Task 9 replaces this per policy — an oracle-reading hook costs materially
more per swap than a constant-fee one, and that gap is precisely what the gas
axis of the matrix measures.

### 3.3 `dex/` is now redundant

Everything needed lives in `contracts/`. Proposed: delete the directory. Not
done — say the word.

## 4. Defects found beyond the plan, and fixed

- **`lib/` in `.gitignore` blocked `git submodule add`** — the pattern matched
  `contracts/lib/`.
- **Submodule pins are load-bearing.** The current tip of `uniswap-hooks`
  changed `BaseHook`'s constructor and made `poolManager` a public immutable;
  every hook here is written against the older API. **On the tips nothing
  compiles.** Pinned to `dex`'s revisions. Also: `git submodule update` resets
  to whatever the index records, so the pin must be `git add`ed _before_
  updating — it silently reverted once.
- **`chainlink-evm` is not needed** and takes tens of minutes; deliberately left
  uninitialised.
- **`MyHook` was undeployable** — no `HookFlags` entry and no dispatch branch,
  so `flags` stayed `address(0)`. Since permissions live in the address bits
  this would have failed at pool initialisation with an unrelated-looking error.
  Added `MY_HOOK_FLAGS` and a `require(flags != address(0))`.
- **`MyHook` lacked the extended fee interface**; without the two-argument
  `setFee` the four static baseline levels could not be set at all.
- **Forge tests share the filesystem.** `setUp()` runs once and tests then start
  from an EVM snapshot, but file writes are never rolled back.
- **`using` is contract-scoped in Solidity** and is not inherited.
