**Goal:** Bring all six policies to a state where they respect the shared fee
box, respond to their declared signal, and can be driven by the replay harness —
plus add the volatility-adaptive policy the paper already claims.

**Architecture:** Each existing hook gets targeted arithmetic and symmetry
repairs, never a change of mechanism. Every repair is paired with a
characterisation test pinning the behaviour that must not change and a test
demonstrating the behaviour that must. `VolatilityHook` is new and follows the
same `BaseOverrideFee` shape as its siblings.

**Tech Stack:** Solidity 0.8.30, Foundry, OpenZeppelin uniswap-hooks, Python for
reference values.

**Depends on:** `2026-08-02-experiment-harness-foundation.md` (Tasks 1–8).

## Global Constraints

- Fee units: Uniswap v4 `uint24` pips — hundredths of a basis point. `1e6` =
  100%. `3000` = 0.3% = 30 bps.
- Fee box, shared by every policy, per direction: `f_min = 100` pips,
  `f_max = 10000` pips. No policy may return a value outside it.
- Policy _mechanisms_ are not redesigned. Only arithmetic defects, missing
  bounds, and undocumented asymmetries are repaired. Where a repair would change
  what a policy means, stop and escalate rather than choose.
- Every repair ships with a characterisation test written **before** the repair,
  pinning current behaviour where it is intended to survive.
- Never run `git commit` unless a step says to.

## Resolved: `PegStabilityHook` Ships as Two Configurations

**Decision taken 2026-08-02: build both readings.** `PegDefence` keeps the
away-from-reference rule; `PegCapture` charges proportional to `|deviation|` on
whichever trade occurs. Task 5 therefore delivers two selectable behaviours
behind one contract, chosen by a constructor flag recorded in the manifest, and
the matrix carries eleven configurations rather than ten. The reasoning that led
here is retained below because it belongs in the paper's validity discussion.

### Background

`PegStabilityHook` currently charges the deviation-proportional fee only when
`!zeroForOne && poolPrice >= referencePrice` — that is, on trades pushing the
pool _further from_ the reference, and only in one of the two directions.

Symmetrising it literally means "tax moves away from the reference in both
directions". But under arbitrage-only flow **every** trade moves the pool
_toward_ the external price, by construction. A literally symmetrised hook would
therefore return `MIN_FEE_BPS` on every swap in our experiment and behave as a
static 1 bps pool.

Two readings, and they are different policies:

- **(a) Peg defence** — tax moves away from the reference. Faithful to the name
  and to §III of the paper. Inert under arbitrage-only flow; the result is a
  legitimate finding about applicability, but the row is uninformative.
- **(b) Deviation capture** — charge proportional to `|deviation|` on whichever
  trade occurs, taxing the arbitrageur for correcting the pool. This is the
  oracle-informed policy that actually captures LVR, and it is what makes the
  hook interesting against the baseline.

Reading (b) is a change of mechanism, which the constraints above forbid without
an explicit decision. That decision was taken: **both ship**, so the comparison
between them becomes evidence rather than an assumption.

### Task 3: Repair `ABHook` delta resolution

`ABHook:126` computes `feeAdjustment = -A * delta / 10000` with `A = 100` and
`delta` expressed in basis points of the square-root price. A 10 bps move gives
`delta ≈ 5`, so `-100 * 5 / 10000` truncates to **zero**: the hook never moves
for anything below a 1% square-root price change, which on one-minute candles is
almost never. It has been effectively static.

**Files:**

- Modify: `contracts/src/ABHook.sol:119-131`
- Create: `contracts/test/policies/ABHookDelta.t.sol`

**Interfaces:**

- [ ] **Step 3: Implement**

Raise the delta scale from `1e4` to `1e6` so a basis-point move survives the
division:

```solidity
        FullMath.mulDiv(uint256(deltaSqrt < 0 ? -deltaSqrt : deltaSqrt), DELTA_SCALE, uint256(lastPrice))
```

`delta = 1000` and an adjustment of 10 pips (0.1 bps) — small but non-zero; a 1%
move yields 100 pips. Record in the commit message that this changes the
effective sensitivity by two orders of magnitude, which is the entire point: the
previous value was unreachable.

- [ ] **Step 1: Write the Python reference and its test**

`experiments/reference/welford.py`:

```python
"""Reference online mean/variance, used to check the Solidity implementation."""

from __future__ import annotations


def welford(xs: list[float]) -> tuple[float, float]:
    n = 0
    mean = 0.0
    m2 = 0.0
    for x in xs:
        n += 1
        d = x - mean
        mean += d / n
        m2 += d * (x - mean)
    variance = m2 / (n - 1) if n > 1 else 0.0
    return mean, variance
```

`tests/test_welford_reference.py`:

```python
import statistics

import pytest

from experiments.reference.welford import welford


def test_matches_statistics_module():
    xs = [3000.1, 3000.4, 2999.7, 3001.2, 2998.9]
    mean, var = welford(xs)
    assert mean == pytest.approx(statistics.fmean(xs))
    assert var == pytest.approx(statistics.variance(xs))


def test_survives_a_large_offset():
    """The naive E[x^2]-E[x]^2 form loses all precision here; Welford must not."""
    xs = [1e9 + d for d in (0.1, 0.2, 0.3, 0.4)]
    _, var = welford(xs)
    assert var == pytest.approx(statistics.variance(xs), rel=1e-9)


def test_single_sample_has_zero_variance():
    assert welford([42.0]) == (42.0, 0.0)
```

calm-market test; a daily sigma of 0.05 adds 1000 pips, clearing the
`assertGt(fee, 1000)` of the volatile test.

$$f = \mathrm{clamp}(f_{\text{base}} + c\,\sigma,\ f_{\min},\ f_{\max})$$

Update at most once per block, reusing the `lastBlock` guard, so the hook reacts
to the reference observation rather than to trade count. Both directions receive
the same fee — this policy is symmetric by construction, unlike `ABHook`.
